## d1 create --json 报错 + 部署脚本两个真 bug

- 报错 `✘ [ERROR] Unknown argument: json`：`wrangler d1 list --json` 支持，但 **`d1 create` 不支持 `--json`**（见 `d1 create --help` 的 OPTIONS，只有 --location/--jurisdiction/--use-remote/--update-config/--binding）。已改为不带 `--json`，用 `parseD1Uuid()` 从 create 打印的 `[[d1_databases]]` 片段里取 `database_id`，裸 UUID 正则做兜底；`already exists` 时重新 list 取回。
- `d1 list` 仍先试 `--json`，失败/解析不出则 `findUuidInListText()` 从文本表格行里匹配同名库。
- 配置里已有真实 `database_id` 时直接早退，不再发两次远端查询。
- **真 bug 1**：`patchSiteUrl()` 里 `patchConfig([/regex/, '$1...'])` 少套一层数组 → `TypeError: .for is not iterable`，任何带自定义域名的部署都会在这里崩。已改为 `patchConfig([[/regex/, 'LIANLIAN_SITE_URL = "..."']])`。
- **真 bug 2**：健康检查对 workers.dev 目标也提示「证书签发中」，改为按目标区分文案。
- 新增 `WRANGLER_BIN` 环境变量覆盖，便于用 stub 端到端自测（stub 覆盖 whoami / d1 list / d1 create / secret put / deploy）。实测链路：建库 → 回填 database_id → 部署 → 写密钥 → 双目标健康检查，全部符合预期。
